## Quick deployment on OKE

The cluster is accessible with `ssh oke-node`; deployments are in the `default` namespace. A changed source tree needs a newly built and published container image. `kubectl apply` only changes Kubernetes resources; applying an unchanged manifest or restarting an old image does not deploy new code.

1. Build and push an immutable image tag for each changed service, using its Dockerfile and the same required build arguments/secrets as its Jenkinsfile. Never put credentials into the repository or command output.
2. Apply only the relevant, reviewed manifests or migration job; retain existing secret values. The frontend manifest contains `${{ secrets.* }}` placeholders, so do not apply that file raw from `oke-node` without rendering and validating the secret source.
3. Set the Deployment image to the new immutable tag, then check `kubectl rollout status` and actual Pod image/digest. The frontend and `maya-sawa` may need separate rollouts.
4. Probe the public routes and authenticated/anonymous permission boundaries, inspect Pod logs, and compare expected database rows and UI data. If verification fails, roll back to the prior image and investigate.

Jenkins is a supported fallback: the frontend pipeline builds `papakao/ty-multiverse-frontend:${BUILD_NUMBER}`, sets the Deployment image, restarts, and waits for rollout. Triggering a build is not proof of deployment; confirm build success, running image, and the public page. Prefer the faster direct path only when image build/push and manifest rendering are reproducible and credentials are available.

## Data-source consultation in progress

### Selected-instrument history ingestion

The user requires three calendar months of history in PostgreSQL, triggered only for instruments entering the fixed/automatic/custom selected set. On first activation enqueue a deduplicated background backfill from selection date minus three calendar months through the latest published trading date. On subsequent activation reuse existing rows and fetch only missing coverage. Schedule daily incremental ingestion for active instruments; retain stored history after removal but stop ongoing collection. Website reads use the database/cache, never start a full crawl per visitor. Expose queued/running/completed/failed coverage status with retry/backoff and resumable checkpoints. Non-trading days and unpublished dates are distinct from HTTP/parser failures; do not generate zero rows for missing publications. Preserve original source units and timestamps and upsert on source/dataset/instrument/observation-date dimensions.

Some official reports return the entire market for one date. Fetch such a report once per date and share the download among selected instruments, but persist instrument rows only for the selected set. For a rolling ten-day calculation, obtain the necessary preceding observations while limiting the displayed requested window to three calendar months. Weekly/monthly datasets retain their native frequency rather than inventing daily values.

### Verified T86 source

The official page `https://www.twse.com.tw/zh/trading/foreign/t86.html` declares `data-api="/fund/T86"`. A live read-only request to `https://www.twse.com.tw/rwd/zh/fund/T86?date=20260713&selectType=ALLBUT0999&response=json` returned `stat=OK`, date `20260713`, 1,335 rows, 19 fields, including stock `2330`. A second request for `20261012` returned `stat=OK`, 1,338 rows, also including `2330`. The non-trading date `20260712` returned no matching data. This confirms dated access at both ends of the proposed three-month window; it is not yet an exhaustive backfill verification.

T86 covers listed-stock daily institutional buy/sell/net shares: foreign/mainland investors excluding foreign dealers, foreign dealers, investment trusts, and domestic dealers split into proprietary/hedging plus totals. It does not supply institutional ownership balances/percentages, margin/short balances, broker branches, main-force metrics, ownership distribution, director pledges/transfers, or futures open interest. The page states historical availability from 2012-05-02. The website adapter can consume official JSON instead of scraping rendered table HTML; retain a CSV fallback only if validated.

Additional official leads requiring per-dataset endpoint/sample/history verification: TPEX for OTC equivalents; TWSE margin and securities-lending reports; MOPS for director holdings/pledges/transfers and issued shares; TDCC weekly holding-size distribution; TAIFEX for futures institutional trading and open interest.
