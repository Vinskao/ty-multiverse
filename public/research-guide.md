# Research 品質準則與 AI 更新 Prompt

版本：2026-10-25。適用：Research 分頁的供應鏈圖、技術圖、三軸評估與研究註記。

這是 TY Multiverse 依公開研究方法整理的作業準則，不是高盛或其他投行的內部 SOP，也不代表機構背書。
研究深度以可驗證、能區分競爭者、能連到經濟結果與可被推翻為準；不以篇幅、術語數或圖中節點數評分。

## 1. 方法來源與使用界線

- [CFA Institute：Industry and Competitive Analysis（2026）](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/industry-and-competitive-analysis)：界定產業邊界，區分產業共同成長與公司市占變化，以五力和 PESTLE 檢查競爭及外部條件。
- [CFA Institute：Equity Research Report Essentials（2020，頁 1–3）](https://www.cfainstitute.org/sites/default/files/-/media/documents/support/research-challenge/challenge/rc-equity-research-report-essentials.pdf)：將產業、競爭、財務、估值與投資風險連起來；注意循環高低點的外推問題。
- [Morgan Stanley Investment Management / Counterpoint Global：Measuring the Moat（2024-10-15；文末 Checklist）](https://www.morganstanley.com/im/publication/insights/articles/article_measuringthemoat.pdf)：檢查資本報酬超過資金成本的幅度及可維持時間。這是資產管理研究文章，不是賣方部門的內部作業手冊。
- [同團隊：Market Share（2022-09-15，頁 1–3）](https://www.morganstanley.com/im/publication/insights/articles/article_marketshare.pdf)：把優勢來源、競爭地位與市占／獲利結果相互驗證，並明確定義市占的市場及計算口徑。
- [Goldman Sachs：Global Investment Research](https://www.goldmansachs.com/what-we-do/research)：公開介紹其基本面研究、預測與模型工作；這一頁沒有提供可直接複製的完整內部 SOP。不得把本指南稱為「高盛標準」。

以下流程、模板和驗收門檻是本專案自己的設計。

## 2. 一篇 research 要回答的八個問題

1. **產業邊界**：研究的是哪種產品、應用、客戶、地區、價值鏈層級與期間？例如測試設備不能直接等同封測服務；800G 模組營收不能當 InP 磊晶市場規模。
2. **誰付款、為何付錢**：需求由終端用量、滲透率、每單位含量、換代、ASP 中哪些因素驅動？訂單是新需求、替換需求還是重複下單？
3. **瓶頸在哪**：物理限制、良率、可靠度、認證、設備交期、合格人力、供電或基礎設施，哪一個限制交付？瓶頸解除後，原供應商的溢價是否消失？
4. **為何這家公司能贏**：以至少一個合適對手和一種替代方案比較同口徑 KPI。產業成長、取得專利或宣稱領先，本身不足以證明公司護城河。
5. **實驗室如何到營收**：分開概念、研發、送樣、客戶驗證、design win、試產、量產、營收占比及獲利貢獻。這些狀態不能互換。
6. **優勢如何到現金流**：解釋數量、ASP、產品組合、良率、產能利用率、研發、折舊、存貨和資本支出的傳導。營收增加但現金流惡化，也必須解釋。
7. **什麼已被期待**：比較公司指引、可取得的市場預期與自己的推論。沒有可驗證共識就寫「無可用共識」。好公司與有吸引力的買價是兩個待驗證命題。
8. **怎麼證偽**：指出最強反方、最早可觀察指標、資料來源、下一次檢查時點，以及發生什麼會改變三軸評估。

五力用來找有經濟影響的議價、替代與進入門檻；PESTLE 只保留會改變上述驅動因素的項目。不必為填框架而寫六段無關總經背景。

## 3. 圖的規則：一條箭頭只能有一種可解釋的意義

### 供應鏈圖

- 分清材料／零件／設備、製造服務、系統整合、終端客戶。標出公司在哪一層、交付什麼、收入如何產生。
- 每條邊標明「材料供應」「製程使用」「散熱路徑」「認證依賴」「競爭／替代」「需求傳導」等關係。
- 合作公告、供應能力、客戶認證、供貨、主要供應商地位分開表述。不得由同產業、自稱供應能力或一張產品照推定客戶關係。
- 關鍵瓶頸、下游議價權與替代供應商要能在圖或相鄰說明中找到。未知的市占與收入占比直接標未知。

### 技術圖

- 先決定是在畫**技術原理／系統架構**、**產品路線圖**還是**商業化進度**。需要多個視角時，用同一 Mermaid 的不同 subgraph；不要把三種關係混成一條鏈。
- 路線圖的箭頭表示有來源支持的後繼／演進；平行產品、同時存在的替代方案和系統零件必須分支。
- 不能將氣冷 → 冷板 → manifold → CDU → 浸沒式直接當成必然升級史；也不能將不同材料、製程平台或公司事業部串成因果。
- 關鍵節點含：技術／產品、成熟度、適用場景或平台、期間／目標時程、證據 ID。例如「驗證中｜目標 2027｜S2」，不可僅寫「先進／領先」。
- 關鍵邊也需要證據；公司 A 的產品證據不能證明 A 是公司 B 的供應商。
- 圖中使用 `[S1]` 等文字證據 ID，來源表提供 HTTPS 文件連結。維持靜態 Mermaid，不加入 click、callback、href、HTML 或腳本。
- 技術名稱與性能不是同一件事。製程名稱要比較同口徑 PPA、良率或成本；材料等級要補頻率、量測條件和產品型號。
- 只畫會改變投資判斷的關鍵路徑；複雜到無法讀時拆 subgraph，不靠增加名詞假裝深入。

## 4. 證據帳：每個重要主張都要可追到文件

先建工作表，再畫圖。最低欄位如下：

| 欄位 | 要填的內容 |
| --- | --- |
| claim ID | C1、C2…，供圖、三軸與結論互相引用 |
| 主張與類別 | 已觀察事實／管理層指引／外部預測／分析推論／未知 |
| 對應對象 | code + market、產品、平台、製程／系統層級 |
| 數值口徑 | 值、單位、範圍、測試條件、樣本／比較對象；未披露則寫未知 |
| 日期 | 資料期間、公告日、讀取日分開；不能用 fetchedAt 冒充公告日 |
| 證據 ID | S1…；文件標題、發布單位、日期、頁碼／章節、直接 HTTPS URL |
| 反方與限制 | 相反來源、是否同源轉載、是否只證明產業而未證明個股 |
| 判斷影響 | 影響哪個技術節點、哪個營運變數、哪一軸；何時重新檢查 |

優先順序：公司公告／法說／年報、監管文件、標準組織／正式規格、客戶與競爭者披露，最後才是可靠第三方分析。
公司自述可證明「公司宣稱／指引」，不自動證明量產成功或競爭領先。競爭對手數據也要標口徑差異。
兩篇轉載同一新聞不是兩個獨立來源。來源首頁只能作入口，不能作特定數字或量產時程的直接證據。
無法閱讀文件或只有摘要時，明確標示；不要補出頁碼、認證客戶、良率或營收占比。

## 5. 技術 → 競爭 → 財務的最小因果橋

每個核心技術至少完成一條可檢查的敘述：

> 解決的客戶痛點 → 相較替代方案的可測 KPI → 客戶採用／付費證據 → 公司取得的份額或單位價值 → 毛利／現金流影響 → 限制與失敗條件。

可以用下列公式拆解假設，但不得用重複計數的因子湊出成長：

- 零組件營收 ≈ 終端出貨 × 適用架構滲透率 × 每系統用量 × 公司供貨份額 × 單位售價。公司份額與架構滲透率的分母要不同且定義清楚。
- 測試需求 ≈ 待測晶片數 × 每顆測試時間 ÷ 並行測試數 ÷ 有效設備工時；再考慮現有裝機、利用率和更新需求，不能直接等同新增設備銷售。
- 現金流檢查包含營運資金與 capex；不要把高毛利當 ROIC，也不要將維持性 capex 一律視為成長投資。

做牛／基準／熊三種情境，列真正有爭議的 2–3 個營運假設、期間和可觀察觸發點。
數字不足時只列假設方向與缺口，不編造 EPS、機率或目標價。估值模型放 AI analysis，Research 保留產業與營運假設及連接點。

## 6. 各產業必問，依商業模式裁剪

| 產業 | 不能省略的問題 |
| --- | --- |
| 晶圓代工／封裝 | 前段製程與封裝分軌；PPA 比較條件、設計成本、良率、有效產能、客戶平台與量產收入；CoWoS 與 SoIC 的互補／整合不能當必然替代 |
| DRAM／HBM | 位元供需、產品別 ASP、庫存、合格產能與良率、堆疊／base die／封裝限制、認證節點；HBM 強勢不代表所有 DRAM 廠受益相同 |
| 光通訊 | 磊晶、雷射晶片、模組、光纖／連接分層；lane rate、功率、可靠度、耦合、封裝與成本；pluggable／矽光子／CPO 的需求轉移與單系統含量 |
| 散熱 | 熱阻、可處理熱負載、流量／壓降、可靠度、漏液、維護與認證；冷板／manifold／CDU／設施水側分層，氣冷和浸沒式另列替代架構 |
| 電源 | 先指定參考架構及日期，列電網／設施／機櫃／板級轉換、保護與備援；PDU 配電不等於 DC-DC 轉換；各級電壓與電源架位置可能隨架構改變 |
| CCL／PCB／鑽孔設備 | 頻率與 Dk/Df 條件、銅箔粗糙度／樹脂／玻纖、層數、翹曲、認證平台；設備需查實際製程步驟、精度、產能、驗收與認列，不能只貼 AI／CoWoS 標籤 |
| ASIC 設計服務 | NRE 與量產收入分開、IP 權屬、tape-out／驗證／量產轉換率、客戶集中、turnkey 承擔、HBM／chiplet 介面證據 |
| 測試機／封測 | SoC、memory、SLT 及測試服務分層；功率／散熱、pin 數／速率、並行數與測試時間；延長測試時間是否被測試效率提升抵銷 |
| 光學鏡頭 | 光學性能、良率、尺寸、可靠度、認證與每機含量；塑膠／玻塑／潛望式／可變光圈是不同設計維度，不能預設同一路線 |
| 網路平台 | 推薦／廣告／生成式 AI／自研晶片分支；轉換率、廣告單價、使用量、推論成本與 capex；開源模型市占不自動轉成平台收入 |
| ETF／基金 | 先讀公開說明書與指數方法；持股權重、集中、選股／再平衡、費用、追蹤差異、流動性、匯率與稅務；技術圖改畫指數曝險與傳導，不虛構基金自身技術護城河；確認是否實體／合成或槓桿結構 |
| 指數期貨 | 不虛構單一發行人的技術護城河；用成分權重、盈餘貢獻、產業敏感度、估值／利率傳導，再分開基差、到期與轉倉風險 |

## 7. 更新流程與品質門檻

先讀現存研究與 revision → 建資料及主張差異表 → 查直接文件 → 重建箭頭關係與技術比較 → 對照財務與反證 → 更新三軸 → 驗圖及內容 → 依既有權限保存 → GET 確認。

事件觸發：新法說／年報／重大技術公告、客戶認證或出貨變更、競爭者推出替代技術、主要假設失效。
僅有新 fetchedAt 不足以改 asOf；記錄實際覆核到的公開文件截點與仍缺資料。

下列六項是交付前必查項；缺一項就標「研究草稿／證據不足」，不宣稱已完成投資級驗證：

1. 重要節點與箭頭都有可查的證據，事實／指引／推論沒有混淆。
2. 至少一個有意義的競爭／替代比較；未披露的欄位如實留白。
3. 至少一條技術到收入、獲利或現金流的因果橋。
4. 至少一個最強反方及具檢查時點的證偽條件。
5. 時程、量產狀態、公司／產品／市場身分一致；關鍵缺口會限制結論。
6. 圖的連線可解釋，文字與圖及三軸沒有互相矛盾，未用圖代替證據。

「格式合法」不等於「內容正確」。本站 JSON／Mermaid 驗證器目前不會替你核實上述六項。

### 三軸偏向與投資評等的界線

沿用本站循環／技術力／交貨的三軸與既有 lean 規則；這個規則是本專案設定，不是投行通用標準。
以已核實證據判斷順風／中性／逆風；資料不足要在 note 明寫「未知／資料不足」，不能偽裝成已知中性。
leanReason 必須寫明重要資料缺口與判斷限制。三軸偏向不等於已完成估值與風險報酬評估，不能單憑兩項順風宣稱股票便宜。
在 AI analysis 另檢查價格隱含預期、估值、風險情境與時間範圍。要改本站評等規則需另外明確提出，不在更新研究時暗改規則。

## 8. 可直接交給下一個 AI 的更新 Prompt

以下整段可以直接使用；先替換目標與資料截點。若無法連網，回報阻礙並產出待查清單，不能聲稱已核實或已保存。

```text
你是 TY Multiverse 的產業研究員兼反方審查者。
任務：依最新、可追溯的公開證據，更新目標的 Research 內容，讓技術圖能支持且能被證偽的營運判斷。
目標：{CODE + MARKET；或「由 dashboard 重新取得目前全部標的」}
覆核截點：{本次實際日期與時區}
先讀完整 https://peoplesystem.tatdvsonorth.com/tymultiverse/research-guide.md 及 market-ai.md。
若尚未部署，改讀 repository 的 public/research-guide.md 與 public/market-ai.md；只有網頁工具且 URL 不可讀時，回報這項限制並請提供指南全文，不能假裝讀過。
不要假裝使用銀行內部 SOP；不要沿用前一模型的技術結論或引用而不覆核。

A. 確認輸入
1. 重新 GET /tymultiverse/api/market/dashboard、research、events 與目標研究紀錄。
   研究紀錄：/tymultiverse/api/market/dashboard/analysis/{recordCode}?productType=research。
   海外用 CODE-MARKET，例如 6857-JP；台灣股票期貨用 underlyingCode；指數期貨獨立處理。
   比對目前標的與研究清單的缺漏；保留離開持股的歷史研究。API 的 stock 標籤不保證是營運公司，ETF（如 009811）需另查證券身分與公開說明書，依基金章節分析。
2. 讀現有 content、revision、asOf；保存原始版本作比較。依 market-ai.md 讀公開 report claims，再做可用的公開報告搜尋。
3. 列出舊研究的三個最重要主張，以及哪些是事實、指引、推論、未知。找會推翻它們的資料，不能只找支持資料。

B. 研究而非擴寫術語
4. 定義產品／客戶／應用／市場邊界。讀最新法說、年報、技術或規格文件及至少一個相關對手／客戶資料。
5. 建 C1…主張表和 S1…來源帳，含文件日期、資料期間、頁碼／章節、直接 URL、限制及覆核日。
   把「公司聲稱」與已觀察交貨分開。不能由產業標準推定公司已取得客戶認證。
6. 回答客戶痛點、核心 KPI 及比較條件、技術瓶頸、替代方案、商業化進度與有效產能。
   KPI 未公開寫未知，不能編良率、單價、市占、產能、客戶名稱或量產時間。
7. 寫一條技術→採用→公司收入／成本→獲利／現金流的因果橋；區分產業成長和公司份額。
8. 提出最強反方、牛／基準／熊的關鍵假設、可觀察事件、證偽條件和下次檢查時點。
   沒有可驗證的共識就明寫沒有，不得自創「市場預期」。

C. 改圖並檢查語義
9. supplyChain 表示交付角色與有證據的關係；technology 以 subgraph 分架構／路線圖／商業化。
   每條關鍵邊標關係，每個核心節點標狀態、適用場景或目標期間與 [S#]。
   平行方案分支；時序、物理連接和競爭替代不得混成同一種箭頭。移除無法支持的公司特定連線。
10. 依本指南六項門檻自行審查，每項回覆「通過／不足＋依據」。不能用節點數或字數當品質證明。
    缺口實質影響判斷時，標研究草稿／證據不足，不強行湊出完整結論。

D. 輸出與既有儲存格式
11. 先交付：舊→新差異表、證據帳、競爭 KPI 比較、因果橋、反方及待查清單。
12. 再交付完整 Research JSON，沿用現有欄位與三軸枚舉，不自行新增前端不會顯示的必填欄位。
```
